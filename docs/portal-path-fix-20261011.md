# Portal 缺口判断与原文路径打包修复

## 改动

增强联合选择（raw + chain + joint）对自带显式 JSON 三元组的原文增加候选路径提示。程序只解析原文中的 subject/relation/object 及实体 ID；按明确 ID 首尾连接，缺少 ID 时只接受无 ID 歧义的完整名称匹配。起点须在问题中按完整词出现，候选终点关系取问题中最先出现的原文字面关系名。不能据此判断整题已满足：问题可能有额外限定，候选路径也可能仅到达内层关系。

不解析任意叙述中的 JSON 示例；带未知限定字段（如 negated、validity）的记录不参与自动连接，避免丢弃限定信息。无自然语言事实抽取、同义词推断、逆向关系推断或事实真值裁决。未识别的原文继续使用原联合选择，仍可作为普通结果返回。

模型同一轮审查收到短的候选原文索引路径和补充指导：跨原文连接可以支持多跳，不要求一句原文重述整个嵌套问题；检查未选中来源中的终点后再报告缺口。只有找到显式候选路径时才增加此提示，普通自然语言选择的提示保持不变。

程序将候选路径包含的来源并入待保留原文，并按路径单独打包，允许新旧路径重复引用共享起点；不以模型 sufficient 为打包前提。审查超时后，已召回且可明确连接的候选来源仍能打包返回。没有新增数据库图结构，源 ID 及证据包映射仍使用现有存储方式。

预算：最多100条已召回来源、6跳、512次路径展开、8条候选路径；每包仍限制6000字符，普通包仍最多4条，路径包最多6条。超长路径保留普通原文回退。top_k 仍限制交付，`omitted_path_source_ids` 明确记录路径来源遗漏，不能保证 top_k=1 同时覆盖新旧两条路径。没有新增 LLM 调用或外部查询通道。
