# Smoke 请求校验修复与可配置并发

2026-10-10 10:14 的服务校验日志显示 `/search` 的 `body.query` 触发 `string_too_long`。原因是本地 AMLSearch 模型设置了 4000 字符上限，官方文本问题超出该限制。移除该本地上限，仍拒绝空白及非字符串输入，不截断问题，不改变检索逻辑。

提交 f28c871 后，服务器真实模型测试接收 5489 字符 query，Search 返回 200、3 条原文且包含正确证据，耗时 7.35 秒。完整自动化测试 322 项通过。没有读取或复制官方私有题目进行分析；修复依据仅是字段校验日志。尚需用户继续原 Smoke 任务确认官方通过。

随后扩展并发配置，取消代码中的 32 上限：

```dotenv
AML_ADD_CONCURRENCY=0
AML_SEARCH_CONCURRENCY=0
```

0 表示不使用应用层 admission semaphore 拒绝并发请求；正整数设置各自上限，负数无效。服务器使用上述 0 配置；模板保留保守默认值 1/4。修改根目录 .env 后重启服务生效，不读取系统环境变量。

数据库锁、ASGI 工作线程以及上游模型配额仍限制实际吞吐；配置 0 不保证 16 个请求同时推理，也不消除上游限流。保留正数模式下 429/Retry-After 行为。两种接口的重叠请求、超过 32 的配置及负数拒绝测试均通过，接口专项共 25 项通过。
