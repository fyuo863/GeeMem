# 多跳来源绑定与证据需求检查

本实验基于 `17bc348`，在 `codex/llm-multihop` 分支实现。两个开关独立，均默认关闭；`.env` 与生产部署未自动修改。`RAG_MULTIHOP_MODE=off` 仍直接走现有参赛检索。

## 配置

```dotenv
RAG_MULTIHOP_MODE=llm
RAG_MULTIHOP_BINDINGS=on
RAG_MULTIHOP_NEEDS=on
RAG_MULTIHOP_LLM_CALLS=5
```

其余模型和预算沿用原配置：gpt-4o-mini、text-embedding-v4、MiniLM，最多三轮检查、六次底层检索（含原问题）、90 秒软调度预算。`LLM_CALLS` 将路由、检查和纠错合计限制在五次；最多一次纠错。旧版无纠错、三轮检查自然最多四次 LLM 调用，故修复版最多多一次调用。预算耗尽不会继续发起下一轮子检索。网络请求仍只使用根目录 `.env` 配置。

## 来源绑定

程序为每个已展示原文 ID 分配稳定、请求内独立的 `E1`、`E2` 编号。`Q0` 只代表原问题，可作为查询起点，不能作为事实证据。

模型不再为后续查询同时拼写长原文 ID、桥接词和完整查询，而是选择：

```json
{
  "source_ref": "E2",
  "quote": "Nadia is married to Elias.",
  "anchor": "Elias",
  "template": "What company does {target} work for?"
}
```

程序验证 quote 在该条可见原文中仅出现一次、anchor 在 quote 中仅出现一次、模板恰有一个 `{target}`。验证通过后，程序计算原文中的字符起止位置，生成绑定编号 `B1`，并代入实体得到实际查询。位置为 Python 字符偏移，末端不包含在片段中；原文 ID、位置和实体共同标识绑定，不按同名实体跨来源合并。

这里保证的是查询锚点出处，不证明所有关系推断正确，也不证明模板其余文字完全符合事实。同名实体的语义消歧仍需要模型结合原文完成；存在重复位置时要求更明确的片段，不猜测位置。首次路由查询仍基于原问题并使用旧版桥接校验，本改动重点处理取得证据后的下一跳。

未知引用、错误来源、歧义片段或状态结构错误可触发一次结构化纠错。纠错输入包含原始问题、同一批可见原文、原候选及验证失败原因。没有可用调用预算时不纠错；纠错仍失败则保留有效证据并停止或按原控制器回退。纯重复查询不会单独触发纠错。

## 结构化证据需求

开启 NEEDS 时，初次路由同时输出最多八个必要事实描述和对先前事实的依赖。程序分配 `N1`、`N2` 编号，禁止依赖不存在的后续项或形成环。后续检查不能删除或改写这份需求清单。

每轮为所有需求返回且只返回一个状态：

- `supported`：引用原文支持，前置需求也已经支持。
- `missing`：必要事实缺失。
- `conflict`：现有事实冲突且未解决。
- `time_unknown`：时间关系或参照日期不明确。

程序检查需求完整性、原文引用和依赖闭合，再计算 `sufficient`。模型省略需求、引用无效或缺少前置关系时，不能仅凭一个布尔值宣布充分。下一跳只能查询尚未解决且前置依赖已满足的需求。

每轮向模型提供固定需求、当前原文和以前通过出处校验的引用，不回传上一轮的“缺失/冲突”结论及其解释，避免小模型复制过期判断。要求它重新扫描当前证据，并将前置关系解析出的实体代入后续关系。完整状态仍保存在程序 trace 中，用于审计和无进展检测。

提示词区分六类需求：关系链、计算输入、事件时间、适用版本、用户偏好和范围完整性。计算题不要求原文写出计算结果；事件顺序不强求无必要的精确时刻；消息时间不能直接代替事件时间；更新不能简单取最新消息；个性化建议应检索用户偏好而非通用建议；统计全集不能用几个例子冒充完整范围。

即使程序计算充分性，原始需求是否完整、引用在语义上是否支持该需求，仍依赖模型判断，不构成事实正确性证明。引用总来源超过原控制器的八条支持容量时不宣布充分，并记录 `support_overflow`。输出 top_k 太小仍可能无法装下完整证据链。

## 停止、兼容与验证

除原有停止条件外，新增统一 LLM 调用上限，以及在后续轮次既没有新候选、也没有支持证据或需求状态变化时的 `no_progress`。停止并不表示充分；只有所有需求通过检查才标记 `sufficient`。

最终仍使用原版融合排序与原文响应结构，未在本轮修改排序权重。`/add` 不调用规划器。模型分析、需求、绑定、纠错信息仅进入请求局部 trace，不写入持久记忆，不出现在公开 `/search` 响应里。

消融测试配置：

| 方案 | MODE | BINDINGS | NEEDS |
|---|---|---|---|
| 基线检索 | off | off | off |
| 原多跳 | llm | off | off |
| 仅绑定 | llm | on | off |
| 仅需求检查 | llm | off | on |
| 组合 | llm | on | on |

两个增强方案共用校验反馈与一次纠错预算；仅 NEEDS 时仍使用旧版查询字段。测试时按题轮换方案执行顺序，减少固定执行次序对耗时的影响，不缓存 Search 查询向量。

```powershell
python -m pytest -q -p no:cacheprovider
# 六个功能场景，其中两个是新增的三段依赖链；小候选池检查真实追加查询。
python scripts/test_multihop_full.py --out data/multihop/new-chain6 --synthetic --ablation --top-k 3 --subquery-candidates 1
# 同一批六类各五题；已有数据库与文档缓存只复制，不修改原文件。
python scripts/test_multihop_full.py --out data/multihop/new-repair30 --per-category 5 --ablation --memory-from data/multihop/stratified30-20261003/memory.sqlite3 --cache-from data/multihop/stratified30-20261003/document-cache.sqlite3
```

自动化测试涵盖三段关系依次发现、错误来源纠正、程序分配位置、未知或歧义引用、需求遗漏与依赖缺失、冲突与时间不明、算术输入停止、一次纠错上限、调用预算、无进展停止、网络失败回退、用户隔离和 Add/Search 原文契约。模拟规划器通过不等于真实模型通过，效果必须以真实调用报告为准。
