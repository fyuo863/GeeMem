# 有界邻接补查与审核窗口试验（2026-10-10）

## 实现与边界

新增 `memory/evidence_groups.py`。底层检索器提供 `expand_neighbors`，仍复用现有 reranker，不新增向量库、不用 LLM 改写事实。

- 只在审核不足且存在明确 missing 后触发；每个请求最多一次，计入查询预算。
- 从当前审核候选最多12个锚点构建同会话前2/后4条的窗口；同一用户、版本可见性、会话范围、事实过滤和脱敏沿用既有控制。
- 每组最多7条原文、3600字符，单条超过1200字符则跳过该窗口；先去重，再用现有 reranker 对小组与“原问题＋缺口”排序，保留最多2组并避免大量重叠。
- 审核最多保留4条旧支持，其余位置优先完整放入证据组及未审核消息；放不下的组显式记入日志。组内位置由程序给出，邻接不作为事实关系。
- 整体仍受既有12条审核上限、轮数、调用数、超时与查询预算控制。第一次失败后可能多一次审核，但不增加常驻判断器。
- 修复恢复任务再恢复自身：所有重试结果回写原任务，防止 Context question 重复叠加。
- 非 off 模式增加保守的停滞检测：审核来源集合、支持集合、标准化缺口文本都没变时停止。语义相同但措辞变化的缺口仍可能消耗剩余预算；没有声称实现完整语义去重。
- 精简持久化位置日志追加来源组和因窗口容量被省略的组。

配置 `RAG_EVIDENCE_GROUP_MODE=off|adjacent|window|combined`。默认 off，本机实际 `.env` 的实验检索开关及服务器配置均未开启。当前结果不足以支持默认上线。

## 实验设计

所有真实实验使用隔离 SQLite、副本语料及根 `.env` 中的服务配置；通过本机 FastAPI TestClient 调用 `/search`，不是服务器性能压测。

1. 两道已知失败题四组消融：`20261010T101042Z`，off / adjacent / window / combined。
2. 补充程序分组顺序标记后，5道人工控制题＋2道失败题对照：`20261010T101351Z`，off / combined。
3. 另外20道同会话真实题对照：从 conv-48 的纯文本 category 2/3 中排除51、75，使用固定哈希排序选择。它们是未用于本轮修改的题目，但共用语料，且部分与开发题共享证据，不能称为独立泛化测评。

所有路径均位于 `data/evidence-chain/`。原始输入、输出、位置、链审核和耗时在各目录 `report.json`；`scripts/report_evidence_groups.py` 生成阶段与来源覆盖摘要。

四组消融共用已修复的恢复任务逻辑，故 off 是“关闭新增邻接/窗口机制”的对照，不是修改前 commit 的逐字复现。每题每配置单次真实调用；LLM仍可能波动，延迟不作为稳定吞吐指标。

### 不能以目标命中代替完整证据链

- 冲浪组合结果选中 D29:30–34；明确提及 surfing 的 D29:24 未进入最终返回，不能仅凭找回“下个月”宣称完整链已解决。
- 审核器仍要求精确日期，且在 split 策略下输出了不必要的连接，链检查标为 invalid。现有 schema / 审核适配仍需改进。
- 冲浪审核选中5条支持，超过证据包4条上限，所以返回独立原文。Top-10可容纳本次支持，不能据此保证 Top-1。
- 人物错配控制题中，“Veda has a brother named Niko”与“Lena has a brother named Pavel”共享 brother，却不共享人物。当前结构校验接受共同字符串，是一次真实的假完整链。新增上下文扩大了这一风险。

## 最终结论

工程机制已实现，目标证据可见性有所改善；语义链质量没有同时得到保证。默认保持 off，不部署。下一步应优先解决“实体同一性与关系词区分”和“有效支持／上下文角色分离”，而不是继续扩大窗口。

自动测试最终结果：389 passed（11.99秒）。新增机制测试覆盖组完整性、用户/会话隔离、脱敏、恢复任务不能递归恢复；这些程序测试不等于模型语义判断正确。
