# 时间增强 Top5 退化：固定候选消融

题目：What is the artist that I started to listen to last Friday?

中文：我上周五开始听的是哪位音乐人？

本轮只分析，不修改检索实现。使用同一份本地 MiniLM 模型，固定为上一轮关闭/开启两组 Top10 的并集，共 11 条候选。该候选集合用于诊断，不是新的全库效果评估。

## 直接原因已复现

| 条件 | 正确证据名次 | 同一原问题下的相关性分数 |
|---|---:|---:|
| 原文＋已有元数据 | 5 | -7.719251 |
| 附加当前时间片段文本 | 8 | -8.014205 |
| 再次使用原文＋已有元数据 | 5 | -7.719251 |

固定候选仍能复现 5→8，说明评分文本变化足以产生这次退化。金标始终在两组 Top10 中，不能把该失败归结为完全未召回。最终 TemporalRanker.operator 为 None，该题未执行 earliest/latest 的日期微调。

## 为什么新增的时间文本没有帮助

金标内容包含“started enjoying their music today”。时间片段 today 被程序归一化为 2023-03-31，该日确实是星期五。数据集提问时间为 2023-04-05（周三），所以 last Friday 与该日期相符。

然而测试 /search 请求只有原始问题，没有携带数据集的 question_date。当前没有对查询侧 last Friday 做参考时间绑定；只是给文档加上 ISO 日期。重排器无法从请求中确定该相对时间的唯一日期。

另外，原有元数据已经在文本开头提供消息日期（31 March 2023）。对于这条 today 证据，当前追加内容有大量重复和说明文字，并非全部都是新增有效信息：

```
Source time mentions (not inferred event dates): today = 2023-03-31 to 2023-03-31
```

MiniLM 的输出是整个 query/document 对的神经相关性分数，没有“加了正确日期就必然加分”的约束。

## 文本级消融

以下均固定原问题，只改变正确证据的评分文本：

| 文本形式 | 分数 | 输入 tokens |
|---|---:|---:|
| baseline | -7.719253 | 102 |
| current_verbose | -8.014206 | 129 |
| short_iso | -7.740002 | 113 |
| short_weekday | -3.414505 | 114 |
| verbose_without_caveat | -7.939329 | 121 |
| iso_only | -7.854581 | 108 |
| caveat_only | -7.749523 | 114 |

- 完整时间增强只有 129 tokens，上限 512，没有截断；这不是上下文装不下的问题。
- 简短 ISO 表达减轻降分，但仍未恢复原分。仅删长说明不保证回到 Top5。
- 明确写出 weekday 的短表达显著提高该文档的分数，说明星期语义对该问题有帮助；这里只做单文档格式诊断，未证明全库通用提升。
- 删除括号说明后仍然降分，因此不能把问题全部归因于 not inferred 这一句。
- 本轮没有 4o-mini 调用；分数变化来自 MiniLM 重排。

## 查询参考时间的验证

在同一固定候选集合、当前增强文档不变的条件下：

| 问题形式 | 正确证据名次 |
|---|---:|
| 原问题 last Friday | 8 |
| 原问题＋Question asked on 2023-04-05 | 4 |
| last Friday 替换为 Friday, March 31, 2023 | 4 |

参考日期来自数据集元数据，而非答案。这个结果支持“查询侧时间参照缺失”的诊断，但不是全量修复验证，也不能直接比较不同 query 下的分数绝对值。

## 原排名很脆弱

原完整实验中第 5 名金标分数约 -7.719253，第 6 名约 -7.719412，相差只有 0.000159。附加文本使金标分数下降约 0.295，足以落到第 8 名。

## 建议

先补充查询参考时间接口，并由程序统一解析 query 与 source 的日期和星期；历史问题不能以机器当前时间为参考。其次，在固定候选上分别保留原文和时间信号，做评分融合消融。不能直接假定短提示、日期文本或某个固定加权必然有效。应复测本次 60 题，重点观察新增时间题与 Top5 退化，同时保留 Top10 收益。
