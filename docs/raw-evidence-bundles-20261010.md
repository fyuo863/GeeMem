# 原文证据包：上层判断关系、新旧事实和事件阶段

本机实验分支 `codex/state-evidence-pilot`，未推送部署。

## 职责

`RAG_EVIDENCE_BUNDLE_MODE=raw` 复用现有多跳规划与检索，在每轮原有审核位置
改为选择原文编号及提出补查问题。检索侧不再输出关系链完整判定，不裁决哪个
事实有效，不将计划自动解释为已经发生的事件。上层回答模型负责这些判断。

选择器每轮最多选 8 个来源，程序绑定来源 ID 和原文，不让模型复制或生成事实。
跨轮保留已选来源，避免下一跳覆盖上一跳的中间证据。来源编号、用户隔离、
版本可见性、脱敏、重复去除和查询预算仍由程序控制。

新模式覆盖旧配置中的 chain、fact replacement、state selector、bindings、needs
开关，使用标准 long 规划路径。旧模式仍可通过 `on` 恢复。原文模式下不会新写
事实替代关系，也不会按已有替代关系过滤旧事实；已有关系记录不删除。
规则适用性和隐私政策维持各自配置，不因原文打包而放开隐私披露。

## 返回

关系、新旧事实、事件阶段共用同一打包器，无第二套向量检索和生成摘要。
只打包检索已返回且被选中的来源，不直接扫库拼接全部历史。模型未选择或底层
没召回的资料仍可能缺失，不能保证每次都集齐新旧值或全部阶段。

每次最多将排名靠前的 8 个已选来源组织为包；每包最多 4 段、6000 字符，超过
时拆包。单条超长原文保留为普通结果，不截掉尾部。包内按来源时间展示，未知
时间放后；这是消息时间顺序，不是事实有效期或事件因果顺序。

每个包占一个 TopK 槽位，每段包含 `source_id`、`source_time` 和完整原文。
包 ID 根据用户、内容计算，数据库仍保存包到各来源的映射。超过 TopK 的包或
普通原文可能无法返回，trace 记录选中但未交付的来源。响应不增加接口字段。

包头明确说明相关性/有效性/阶段未裁决，不输出模型生成的关系、阶段名或“新值
有效”等标签。即使收集未完成也可返回已有原文。内部兼容字段 `sufficient`
在此模式仅表示选择器停止补查，不代表证据链正确或已经给出了答案。

## 模型成本与保护

没有新增独立 LLM 调用；替换原审核，沿用现有轮数、调用次数、输入长度、HTTP
超时和查询预算，不加隐藏重试。上下文扩展开关不自动开启。实际调用次数仍
可能因补查策略变化而增加。来源越界、供应商失败沿用原回退路径；不会伪造包。

测试不调用上层回答模型，因此只评价原文交付和来源完整性，不报告答案准确率。

## 实测结果

自动化回归 398 项通过。真实提供商调用采用本机 FastAPI TestClient 和隔离库，
6 道人工构造题、2 道 LoCoMo-Refined 真实题，共 24 次 Search：首轮旧/新各 8 次，
修复跨轮来源丢失后再跑新模式 8 次。全部 HTTP 200，无检索回退。
合成资料经真实 `/add` 写入；真实数据题复用冻结语料，不是新的全量写入测试。

合成题请求 TopK=1，真实题 TopK=10。表格只计算目标来源是否返回；例如不同人物
反例还混入了 Lena/Pavel/Selene 的来源，1/1 不意味着消除了无关内容，只表示
上层现在也能看到 Veda/Niko 的起点原文。包不再声称这些来源构成正确链条。
缺失结果案例没有生成结果，真实宠物题仍未找齐目标来源。冲浪题只证明标注的
目标原文返回，不能据此保证话题连接和完整语义证据链。未调用上层回答模型。

两模式各 8 题，中位耗时 8.30→14.01 秒，LLM 调用总数 20→25。额外消耗来自
补查轮次，不能将复用审核调用解释成总调用数不变。比较是同一配置关闭事实
替代/状态选择的 `on` 与 `raw`，不是线上历史提交的独立重跑；模型/API 有波动。
测试样本小、含开发案例，不能推断比赛成绩或泛化提升。
