# 可追溯证据链试验（2026-10-10）

实施前检查点：`9ede418`。分支：`codex/state-evidence-pilot`。

结论：本轮证明了“保留中间证据、拒绝把断链当作完整链”的价值，尚未证明能修复真实难题的缺失召回。不建议据此部署或宣称官方 B2 等能力已解决。

## 实现

- 新增 `memory/evidence_chain.py`，将审核器选中的原文绑定为节点；来源 ID 取自实际召回记录，模型只引用已有 ID、选择引用片段及连接索引。
- 审核器在原有调用内选择 `parent/child/bridge`。程序绑定真实来源，验证引用逐字存在、连接索引合法、方向无环、桥接短语同时存在于两端。
- 不再按排列顺序伪造 `derived_from`。独立比较（split）的证据没有强制父子关系；单条原文也可能含完整关系链。
- chain 检查问题起点是否出现在首条证据中；英文单一显式姓名允许从属格短语中取出。别名、隐式人物及非英文改写仍可能被保守判为不完整。
- 完整性必须同时满足模型充分性判断、原文校验及适用的结构检查。`complete` 表示来源有效且模型判定充分，**不是程序证明语义正确**。
- 模型声称充分而结构检查失败时，最多反馈修复一次，仍受原有轮数、LLM 调用、查询和耗时预算限制。模型改为不足后可执行常规补查；不无界重试。
- 证据包保留原文、来源 ID、时间、hop 和已验证的来源连接；partial/invalid 包标明状态，不生成答案。上限仍为 4 条来源、6000 字符。
- 记录 `returned_source_ids`、`omitted_source_ids`、`delivery_complete`。后者仅指“已选证据是否全部交付”，不代表问题已可回答。超过证据包限额会退回原文 Top-K 并记录遗漏。

## 配置与模型压力

默认关闭，实际 `.env` 与服务器配置没有修改。隔离试验使用：

```dotenv
RAG_EVIDENCE_CHAIN_MODE=on
RAG_EVIDENCE_BUNDLE_MODE=on
RAG_MULTIHOP_PROMPT_STYLE=long
RAG_MULTIHOP_BINDINGS=off
RAG_MULTIHOP_NEEDS=off
```

本版不支持 focused、bindings 或 needs 审核适配器与证据链同时开启，启动时明确报错，避免静默绕过。阶段选择器遇到 chain 时使用标准连接审核。

不新增常驻模型调用；沿用 gpt-4o-mini 审核，每次至多 8 条支持、12 条连接，候选输入仍由既有 evidence 数量/字符预算限定。连接校验为程序操作。发现结构问题可能触发一次额外审核及预算内补查。本次 7 题 LLM 调用总量由 17 增至 21，中位端到端耗时由 7.06 秒增至 9.53 秒；单次运行，不是稳定延迟基准。

## 两道真实题的具体问题

### 宠物比较

问题：Which pet did Jolene adopt more recently - Susie or Seraphim?

关键线索是 D2:22 中的 Seraphim、D2:24 的 “I bought it a year ago in Paris.”、D16:5 对 Susie 的提问与 D16:6 的“两年前收养”。D2:24 没有宠物名，需要把它与前文指代关联。

本次模型仍选中“前天买的新鱼缸”的片段，不能把鱼缸购买时间当作收养时间；新审核最终承认缺少收养证据，错误桥接被程序拒绝，但没有找回 D2:24。

原金标还包含 D2:28：“Even as a child I learned to play on my own.”，其前后文为电子游戏，不能支持宠物收养比较。本报告保留官方数据原始金标，未为提高指标自行修改；同时单列此人工发现。

### 冲浪约定

问题：When did the Deboran and Jolene agree to go surfing?

D29:24–30 建立 surfing 话题，D29:33 询问哪一天，D29:34 回答“Let's plan for next month - I'll check my schedule and let you know.”。终点原文没有 surfing 一词，距离首次提及话题较远，短邻接上下文不足以恢复话题。此次没有召回 D29:34，仅给来源加连接标签无法解决这个候选缺失。

## 下一步与上线边界

1. 优先做同会话话题范围内的有界邻接补查：从已找到的 Seraphim/surfing 话题片段向后取候选原文，以真实 ID 独立交给审核器，不能把上下文冒充目标说话人的事实。
2. 区分“命名实体片段”和“代词/日期回答片段”，以原问题、话题原文、回答原文构成小证据组。限制窗口、候选数与补查次数，避免无界拼接。
3. 连接校验继续作为来源/结构保障，语义判断不能仅凭共享名字通过；加入更多同名、否定、跨人物和错日期控制题。
4. 用未参与开发的真实题验证完整链率、错误链率、无关证据比例和耗时，再考虑开启默认配置。当前不部署，也不宣称事实替代、规则、时间治理或隐私已因此解决。
