# 多跳提示词优化与错误题复查（2026-10-03）

本次按用户要求先优化提示词，不修改检索算法、融合权重、输出 schema 或默认开关。另增加原始路由候选 trace，便于定位依赖编号校验失败；评测脚本支持显式选题和冻结旧提示词的同代码对照。

## 修改内容

1. 先识别依赖链，逐条解析原问题中的关系，保留最终属性；未知的复合主体不能作为单个事实需求。
2. 单一已知主体的属性问题只需要最小事实，避免多余身份、日期、配料或背景需求；算术只需要操作数和适用范围。
3. 引用判断先代入前置需求解析出的主体，再核对主体、关系、客体；亲属关系不允许转移教师、雇主或经历。
4. 用正反例区分真实发生的事件、计划、建议和相关话题；查询模板必须符合锚点类型及语法角色。
5. 保留 gpt-4o-mini、原文返回、用户隔离和查询预算。两个增强开关仍默认关闭，多跳实验未部署。

## 对照协议

最终比较 baseline（FM 无 LLM）、previous（旧提示词，来源绑定＋需求检查均开启）、combined（新提示词，同样开启两项）。previous **不是**此前表格中关闭两项增强的“原多跳”。通过每个 planner 实例替换指令字符串回放旧提示词，其他代码、参数和输出 schema 相同；旧指令已核对与提交 `ad8859a` 完全一致。

使用项目根 `.env` 的 gpt-4o-mini、text-embedding-v4、MiniLM CUDA；API Key 不进入报告。只复用文档向量，不缓存查询向量。通过 TestClient 调用真实 Add/Search。按题轮换方案次序。回退计入主表，单独披露错误类型。

## 最终判断

提示词带来了局部改善，没有证明总体召回提升。公开 10 题中新旧组合版 Recall@10 均为 88.33%；新提示词仍会误判关系归属与事件真实性，因此不默认启用。

- 职业 `5d3d2817`、钓鱼数量 `21436231`、5K 成绩 `6a1eabeb`、腌制时长 `faba32e5`：新版在最终主运行中只生成一个必要需求，并在找到原文后停止。腌制题的旧版当次有网络回退，相关定性对比还参考已保存的前轮错误 trace，不能用该题当次耗时证明加速。
- 受控 Iris→导师→公司→总部链：旧提示词命中 2/3 并因无有效查询停止，新提示词命中 3/3。两者均未回退，构成该次运行中的实际改善。
- 受控亲属/教师题：新版仍将“Veda 跟 Pascal 上课”错误传递为“兄弟 Niko 的老师是 Pascal”，命中 1/3 却宣布充分，未修复。新计划还把“兄弟的老师”合成一个未知主体，没有遵循逐关系拆分规则。
- 旅行排序 `gpt4_7f6b06db`：新版仍用黄金周建议和收到邮票推断已经发生的旅行，命中 1/3 却宣布充分。查询仍偏向集邮等无关主题，未修复。
- 餐厅推荐对照题 `4c36ccef`：正确原文已找到，但新版仍额外要求确认用户身份，最终停止于无有效新查询。简单问题过度规划只是减少，并未消除。

最终主运行公共题旧版 3 次、新版 4 次 ConnectError 回退；受控场景旧版 2 次、新版 0 次 ConnectError 回退。未出现第二轮的路由 ValueError。主表保留全部回退。公共题双方均无回退的配对交集只有 5 题，Recall@10 均为 86.67%，平均耗时 15.12→14.23 秒；受控配对交集 4 题，Recall@3 为 75.00%→83.33%。均为小样本，不能外推稳定收益。

另对主运行中新版网络回退的四题进行一次补充复查，目录 `prompts-v3-network-recheck4-20261003`。补查单独展示，**不覆盖主表、不择优拼接结果**。

下一步若要真正阻止错误关系进入后续检索，需要程序层面的变量/角色约束及证据语义验证。继续仅增加提示词条款不足以形成正确性保证。
