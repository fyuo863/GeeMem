# 状态证据选择试验（本机，2026-10-10）

分支：`codex/state-evidence-pilot`，基于 `aeedc60`。未部署远端。

## 实现范围

这是查询时的证据选择试验，不是持久化事实状态管理。`/add` 仍保存原文及原来的类型索引；不生成新事实，不删除、覆盖旧记忆，不建立 supersedes 或有效期表。

现有 SearchService 完成规划、分区、底层召回、重排和多跳后，新模块 `memory/state_evidence.py` 对结果进行一次可选处理：

1. 仅当前值、更正、冲突、规则等中英文词命中的问题触发；问题超过 1500 字符则跳过。
2. 为避免 top_k 很小时失去候选，触发时内部至少保留 16 条，最终仍返回请求的 top_k。
3. 只提供前 16 条中不超过 600 字符的完整原文；长原文保留原排序但不交给本模块，避免截断更正内容。
4. gpt-4o-mini 仅选择候选下标、精确引文及 primary/context 标签，最多 8 条，不生成答案。
5. 程序检查下标、引文和重复选择；primary 优先、context 次之、其余最后，同级保留原排序。旧证据不永久删除；最终 top_k 仍可能截去低位证据。
6. 错误或无可靠选择时保留上游结果。原文 ID、content、created_at 不变；排序变化时按原分数降序序列重新分配 score，score 不代表事实可信概率。

配置：根目录 `.env` 中 `RAG_STATE_EVIDENCE_MODE=on/off`；默认 off，本次未修改本机或远端 .env。每个触发请求最多额外 1 次调用，HTTP 超时 20 秒、无内部重试；这个预算独立于原多跳预算，HTTP 超时不是端到端硬截止。输入至多约 9600 字符原文加问题、元数据；沿用原适配器最多 1800 输出 token。

新增日志只有状态枚举、候选数、选择数、调用数和耗时，不记录问题、用户 ID、原文、密钥或异常响应体。测试报告中的原文和模型输出均为人工构造公开示例；现有调试 trace 并非全局脱敏日志，不应直接打印到生产日志。

## 验证方式

- 回归：`python -m pytest -q -p no:cacheprovider`，337 项通过。
- 本机接口：`python scripts/test_state_evidence_real.py`。FastAPI TestClient 请求 `/health`、`/add`、`/search`；真实调用根 .env 配置的模型供应商，使用隔离 SQLite 数据库。12 个中英人工案例覆盖当前值、更正、未来意向、回顾旧事、未消解冲突、不同人物、默认规则和例外，以及历史、时间先后、多跳、普通事实对照。
- 固定候选池：`python scripts/test_state_selection_pool.py`。8 个状态/规则案例，故意把正确原文放到 12 条无关信息之后；固定候选顺序，仅调用真实选择模型，用于隔离上游规划随机性。此项不是自然检索效果指标。
- 复测同一隔离库：`python scripts/test_state_evidence_real.py --reuse data/state-evidence/20261010T024712Z`。相同 request_id 复用已有写入，所以不衡量第二次写入的构建耗时。

## 固定候选池结果与失败原因

首版只有“选中/未选中”，8 题中 5 题把全部金标放进前 N 条（N 为该题金标数量）。增加 primary/context 后复测仍为 5/8，不能认为提示词修改解决了问题。

| 案例 | 最终结果 | 模型实际问题 |
|---|---|---|
| Mei 当前住址 | 失败 | 把 `Mei lives in Paris.` 与明确更正 `Correction: Mei moved from Paris to Rome and now lives in Rome.` 都标为 primary，旧值继续在前 |
| 小林当前公司 | 失败 | 把“在甲公司工作”及“已经离开甲公司，目前在乙公司”都标为 primary |
| Omar 当前雇主 | 失败 | 当前在 Cedar Labs 与尚未接受的未来 Maple Labs 意向都标为 primary |
| Nina 当前住址与回顾旧址 | 通过 | 当前 Oslo 为 primary，回顾 2020 年 Lima 为 context |
| Alex 地址冲突 | 通过 | 保留双方，未强行判断哪方有效 |
| 李明/李华区分 | 通过 | 目标人物证据进入首位 |
| 英文默认规则和例外 | 通过 | 保留默认规则及急诊出租车例外 |
| 中文默认规则和例外 | 通过 | 保留值班规则及支付故障例外 |

这说明来源合法、引文真实并不意味着状态判断正确。程序验证可以阻止虚构引文，无法由此证明“已经替代”“仍未生效”等语义成立。把选中证据整体前置，也不能自然获得正确的当前值。

初版 12 题接口小测中，基线与增强的 Recall@10、首条金标命中率、前 N 条全证据命中率均为 100%。每个用户仅有 2–3 条原文，因此存在明显天花板，只能视为接口/原文/隔离检查，不能推断竞赛能力提升。最终代码复测汇总另见同目录 JSON 和下方补充。

## 结论与边界

最终代码的 12 题接口复测：

| 指标 | 基线（关闭） | 增强（开启） |
|---|---:|---:|
| Recall@10 | 100% | 100% |
| 首条金标命中 | 12/12 | 12/12 |
| 前 N 条全金标命中 | 12/12 | 12/12 |
| 平均 /search 耗时 | 6.04 秒 | 7.06 秒 |

12 次幂等 `/add`、24 次成对 `/search`、`/health` 和空用户隔离检查均通过；8 次选择调用、4 次跳过、0 次选择失败回退。平均请求耗时增加约 1.02 秒（16.8%），包含独立两次运行的上游波动，不完全等于选择器自身耗时。四个非触发对照题没有新增选择器调用。

这些是同一套中英人工案例；未运行新的完整公开数据集或官方私有评测，不能把上述 100% 当作泛化或比赛成绩。

暂不默认开启或部署。此试验验证了接入和失败回退，但没有证明自然检索收益；在刻意打乱的排序中，当前值判断仍有 3/8 失败。

下一步应单独评估“两个同主体同属性的来源是否存在明确替代、未来意向、无法消解冲突”，而不是继续把相关性选择等同于状态裁决。先验证成对判断准确性与成本，再考虑程序化状态版本记录；不能对所有消息简单采用最新时间优先。当前试验也未完成删除/遗忘、隐私披露策略、全局摘要、时间窗口或因果链修复。
