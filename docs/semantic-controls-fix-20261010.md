# 规则、阶段、事实替代与语义披露修复

检查点：`cbfc0a0`（修改前先提交）。分支 `codex/state-evidence-pilot`。
本轮只修改本机代码和根目录 `.env`，没有推送、部署或修改服务器配置。

## 问题定位与修改

1. 普通通勤仍混入急诊例外：旧审核只检查“相关”，回填还能再次带回例外。
   新 `rule_applicability.py` 独立判断适用性，在拼接前同时过滤 supports 和 ranked。
   只判断最多 12 条、每条 900 字符；成功后不回填未经审核的尾部。
   从现有多跳 LLM 预算预留一次调用，不增加配置的调用上限。
   模型失败、预算耗尽仍可能返回原候选，trace 明确记录 unknown/budget_exhausted。
   仅适用于当前 long/short 多跳路径，不是服务端访问控制。

2. 泛化补查没有增加覆盖：实验中原计划已在候选池，但审核只引用了变更与结果。
   新 `stage_review.py` 对同时询问计划、变化、最终结果的问题，用三个来源编号
   选择替代原通用审核，缺失阶段返回 -1，程序生成相应补查提示。
   这不增加审核调用次数，也不让模型生成原文。并非任意事件类型的通用状态机。
   其他阶段/规则补查改为仅在存在缺口、没有可执行查询时触发，一次查询上限不变。
   “无需补查”与“补查增加召回”现在可以分别在 trace 中观察。

3. 事实替代：`rag_fact_relations` 保存同用户的新旧消息 ID、关系与程序绑定原文。
   每次 Add 最多检查 2 条显式更新消息，每条只比较词面预筛的 4 条旧来源。
   只比较已发布、时间更早的消息；模型仅选 replaces/conflicts/unrelated/unknown。
   计划/愿望/假设预筛与读取保护避免把未来愿望当成已生效更新。
   当前值问题只排除整条被替代的单一旧事实。复合消息、历史问题、冲突、不确定关系保留。
   新旧证据仍可由现有证据拼接器返回，不保证每次自动成对输出。
   读取固定版本并检查新事实是否可见；参考时间早于新来源时不抑制旧来源。
   词面候选、显式更新触发词及原子消息限制会漏掉隐式更新，这是保守边界。

4. 语义披露：模型仅选择片段编号与类别，偏移由程序生成。类别为 health、finance、
   intimate、legal、contact、identity、credential。最初的复制原文方案在真实调用中
   出现改写和遗漏，已改成 public/sensitive/unknown 加编号选择。
   每次 Add 最多 2 批、每批 8 条、每条 900 字符/24 片段。
   未标注、失败、越界、未知或内容哈希变化的消息不进入召回，不默认视为公开。
   grants 仅由根目录 `.env` 提供，用户问题不能改变授权。
   假定上游服务正确验证 principal；当前共享服务凭据不能自动识别最终用户本人。
   语义误标仍可能漏保护，不能当成经过安全认证的完备 DLP 系统。

## 预算与运行配置

新增 Add 判断最多 4 次调用，单次 20 秒，没有隐藏重试；最多新增约 80 秒网络等待。
重复原 Add 可重试缺失的隐私标注，向量与已完成标注不会重复写入。
超出批次上限的内容保持未知，需再次处理，不能宣称大批量 Add 均已完成标注。
事实判断失败保留原检索行为；隐私判断失败采用不披露行为。
Add 的 embedding、分类和标注仍会将原文交给配置的提供商；本功能保护检索披露，
不解决提供商侧的数据处理授权。

本机已开启：版本固定、基础 mask、规则适用性、事实替代、按缺口补查/阶段选择。
语义隐私保持关闭：旧库没有全量敏感标注，直接开启会隐藏未标注旧资料。
新隔离库可开启 `RAG_SEMANTIC_PRIVACY_MODE=on`，同时设置 `RAG_DISCLOSURE_MODE=mask`。
配置示例（仅示例身份，不是当前授予的权限）：

```dotenv
RAG_DISCLOSURE_PRINCIPAL=my-trusted-service
RAG_DISCLOSURE_GRANTS={"my-trusted-service":{"user-001":["health"]}}
```

默认 grants={}，无通配授权；基础邮箱/电话/凭据遮蔽不能被上述语义授权覆盖。
授权变更后重建后端/重启服务；模型不会解释 query 中的自称身份为授权。

敏感片段越界、失败重试、旧库无标注、权限授予/撤销、重排前遮蔽与原文保留。

关/开使用同一个隔离数据库、相同 TopK=3；before 关闭新增语义控制，基础 mask 保留。
