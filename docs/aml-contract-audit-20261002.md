## 核对结果

| 项目 | 官网要求 | 当前实现 | 结论 |
|---|---|---|---|
| Add 请求 | request_id/messages/user_id/session_id 必填 | 字段一致，ID 原样回显 | 符合已公布结构 |
| 消息 | role 为 user/assistant，content 为字符串，保持来源顺序 | 按输入顺序写入并保留来源位置 | 符合 |
| timestamp | 可选，Unix 毫秒 | 接受整数或省略，未知时间不伪造 | 符合 |
| Add 响应 | 持久化且立即可检索后返回 success=true 和三个 ID | 同步事务完成后返回 HTTP 200 | 符合 |
| Search 请求 | query/user_id/top_k，选择题顶层 options | 支持开放题与顶层字符串选项数组 | 符合 |
| 正式 top_k | 固定 100，表示允许返回的最大条数 | 支持 1–100，结果不足时可少于 100 | 符合；不能把 Top10 指标当成正式成绩 |
| Search 响应 | data 必填，按排名排列；稳定 id、非空 content | 返回原文分块、稳定哈希 ID、排序后的 data | 符合 |
| 可选响应字段 | score 越高相关性越强；created_at 来源或持久化时间 | FM 返回最终排序分数，源时间未知时省略 created_at | 符合当前配置 |
| 空结果与隔离 | data=[]；按 user_id 隔离 | 无数据返回空数组，不混入其他用户 | 符合 |
| 鉴权 | 提交时说明鉴权方式 | Bearer，亦支持配置 Token/x-api-key | 应与已绑定资料保持一致 |
| 赛道 | 文本字符串；多模态为 ContentPart[] | 当前只验证文本；多模态数组会返回 422 | 仅申报文本赛道 |

## 尚不能无条件承诺的部分

1. **输入容量不是官网保证的上限。** 当前限制为每次 Add 200 条消息、每条 32,000 字符；query 4,000 字符；最多 100 个 options，每项 4,000 字符；ID 256 字符。官网当前页面没有承诺全部输入均小于这些限制。超限会返回 422，不会截断。这些限制需要与提交的容量资料及官方 Smoke 核对，不能据结构一致断言所有 Full 输入必然成功。
2. **扩展元数据并非官方必传。** speaker/session_timestamp 是我们的可选扩展，官网只保证标准字段。缺失姓名元数据时人物软召回不触发；缺失全部时间时日期通道不触发。角色不同仍可用于局部问答关联。不能将带扩展元数据的公开集指标直接作为标准官方输入下的效果。
3. **Top10 不是官方最终评分。** 正式 Search 要求 top_k=100，并将返回内容按顺序送入 Answer。已有 Hit/Recall@10 只是本地证据检索指标；未在本次重新测量完整 Top100 质量与 Answer 成绩。
4. **评测数据保留政策需要运维落实。** 官网规定仅用于本次评测，不得用于训练、额外分析或共享；保持私密、避免日志，并在结束后 30 天内删除。当前启动命令关闭 access log，验证错误不回显请求正文，但 SQLite 没有自动到期删除机制。必须管理正式数据与副本/备份清理；公开开发集与官方评测数据需分开。
5. **运行与申报状态。** 当前本地版本已选 FM，远端本次未更新。官网要求固定系统版本、稳定公网接口、绑定地址/鉴权/容量，先 Smoke 后 Full；不能将本地测试视为这些步骤已完成。指南本页不能单独证明模型在所选榜单的资格。

本次没有发现标准文本请求/响应的字段不匹配，未更改业务排序或接口 Schema；补充了 Top100 回归验证与 README 的正式 top_k、options 和元数据边界说明。
