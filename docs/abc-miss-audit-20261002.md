# ABC Top10 未命中诊断

## 范围与可复现性

分析基于远端 7491cfe、BGE-small-en-v1.5 / MiniLM-L-6-v2，冻结评测运行 bge-baseline-20261002T073855Z。861 道纯文本题中，859 道有证据标注。ABC 命中 796 题，完全漏失 63 题；完整证据命中 745 题，另外 51 题只命中部分证据。总计 114 题存在缺失，漏失 155/1,074 条证据。

诊断使用线上 SQLite 的一致性副本、新建进程、相同模型与配置，未改变线上程序。对 114 题运行真实 search，记录各阶段；扩大返回至 Top100，但候选池仍为 400，114/114 题的前十个记忆 ID 与冻结 HTTP 结果完全一致。未用金标干预检索或排序。完整阶段输出见 cases.jsonl；复现脚本见 diagnose_abc_misses.py。

## 主要发现：候选内排序是瓶颈

| 155 条漏失证据的去向 | 数量 |
|---|---:|
| 首轮已进入 400 候选 | 138 |
| 被二次检索补入并直接评分 | 4 |
| 未直接评分、靠邻居传播进入最终排序 | 11 |
| 最终排序仍不存在 | 2 |

这些是按“问题—证据”计数，不是全局去重后的消息数量。155 条均存在于存储中，没有证据丢写。在 63 道零命中题中，58 题至少有一条金标已被直接重排评分，仅 5 题的全部金标都未直接评分。扩大候选数量不能解决已评分却低排名的问题。

|---|---:|

当前排序如果允许返回 Top20，Hit 可达 95.46%；Top50 可达 97.44%。这仅说明候选中存在证据，不能当作保持 Top10 时可自动获得的提升。

## 原因与真实案例

### 1. 话题相关性压过答案证据

conv-42 / q35 问 Joanna 和 Nate 都看过哪些电影。标注证据包括《小妇人》《指环王》。其中 D3:17 向量排名第 4，混合召回第 15，但上下文重排第 61，最终第 43。前三名却主要在谈喜欢哪些电影类型、两人有共同兴趣。说明模型找到了电影话题，却未有效区分“看过某片”与“谈论电影”。

这也是多人交集问题：单条消息不一定同时包含两个人的完整答案，直接以完整复杂问题给单条消息打分，会压低各自的有效证据。应试验按人物拆分子查询、再合并证据，而不是要求每条消息独立满足全部条件。

### 2. 短回复、代词与上下文关联不足

conv-26 / q73 问 Melanie 对 Caroline 收养孩子的决定怎么看。金标 D2:15 是 “You're doing something amazing! ... You'll be an awesome mom!”。没有名字与 adoption 词项；初召回第 349，上下文重排第 160，邻居加分后仍为第 56。第一名是 Caroline 自己提交收养申请的陈述，并非 Melanie 的态度。

conv-42 / q78 的实际回答 D3:6 是 “Super good! It was rich and creamy...”，上下文重排第 56，经邻居传播提升到第 12，仍被挡在 Top10 外。

63 道零命中题中，22 题至少一条证据距离当前 Top10 某条结果仅相邻 1 条，扩大到同会话前后 2 条时为 29 题；两者重叠，不可相加。这是支持试验局部问答关联的诊断覆盖量，不是预期净增益。

### 3. B 的目标校验对依赖上下文的证据存在误伤

conv-50 / q36 问 Calvin 和 Dave 对哪位家人有怀念。D12:2 和 D20:6 都提及 dad，上下文分支分别排第 8、第 9；目标独立打分与融合后排第 11、第 12，最终第 12、第 14。这题基线命中、ABC 失败。

另一例 conv-30 / q38，简短回答 “Yeah, awesome! Glad to be part of it.” 从上下文第 10 变为融合第 11。

63 道零命中题只有这两题在上下文单分支曾有金标 Top10。因此融合不是全部失败的根源，也不应直接删除 B。全部漏失证据中，21 条在目标单分支可排进 Top10，融合结果却未命中，表明固定权重同时会压制两种不同的有效信号。

当前融合为 context + 0.25 × clip(target−context, −2, 2)，目标分支对单项分值最多调整 ±0.5。应试验保留两个排序分支的候选，再对短回复、完整事实句分别处理，且在全量数据上检查净收益。

### 4. 人物和日期没有参与初召回

现有 embedding 与 BM25 使用原始 content，人物和时间仅进入重排文本。conv-41 / q88 明确问 Maria 在 2023-06-03 提及的新活动，D17:12 是每月到狗收容所做志愿者，混合召回第 583，未获得直接评分，最终仅靠邻居传播排第 318。

可增加人物/会话日期匹配的独立召回通道，作为软合并而非强过滤。说话者未必是事实主体，会话日期也不总等于事件日期；“昨天”“三年前”“计划做”不能直接按记录时间等同处理。

### 5. 标注覆盖或质量问题

conv-48 / q72 问 Jolene 与伴侣在 2023 年 9 月主要待在哪里，答案为 Phuket。Top1 D27:1 明确写了与伴侣到 Phuket 度假数周；金标却指向 D2:1，一条 Deborah 谈父亲去世的消息。至少存在明显的证据 ID 错配嫌疑，不能为了命中这个 ID 去扭曲检索。

conv-30 / q58 问 Jon 告诉 Gina 自己不会做什么，答案是 quit。金标 D14:17 为 “I'm not giving up.”；Top1 D13:23 为 “I won't give up, Gina!”，Top2/3 也明确说 “I won't quit”。这是标注证据未命中，但并不等于没找到可回答证据。

上述为具体案例审阅，不宣称已完成全部样本的语义可回答性审计。保留严格证据 ID 指标，另建人工核验的等价证据记录，不能把替代证据自动算作官方命中。

## 优先试验顺序

1. **Top20–50 的证据筛选与局部问答关联**：维护 context、target 两路排序；对高分提问/话题引入其同会话后续回答，对省略回答补前文指代；最终仍返回十条原文。优先观察贴近边界的 24 题及 9 道基线命中而 ABC 退化的题，不能只在这些题上报分。
2. **多人/多条件子查询合并**：对 both、共同、列举等结构分别检索每个人的事实，合并时保障不同证据覆盖，避免泛泛的共同兴趣或重复寒暄占满十个位置。
3. **人物、日期软召回补充**：补救已有元数据却未进入重排池的样本，不必直接将候选从 400 全面提高至 800。优先保证明确时间与主体条件的消息能被直接评分。
4. **标注审计与独立验证**：固定当前金标不变，分别记录疑似标注错误和等价支持。用未参与规则调整的会话做验证，同时报告全量 Hit/Micro Recall/全证据命中和延迟，防止只提高失败子集而伤害原有成功题。

目前为诊断与优化建议，尚未修改或部署上述策略，不能把候选覆盖量当作性能提升承诺。
