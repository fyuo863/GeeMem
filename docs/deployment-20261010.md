## 重试行为

|层级|当前行为|
|---|---|
|写入分类器、独立分区判断器|最多 3 次尝试；暂时性 HTTP 故障及结构验证失败可重试；401 等永久性故障不重试。退避 0.25、0.5 秒|
|Qwen 重排|默认重试 1 次，即最多 2 次请求；覆盖网络/超时和 429、500、502、503、504。401 不重试；遵守有限 Retry-After|
|多跳 LLM 规划|不添加隐藏重试；调用预算由编排层控制，失败时回退基础检索|
|Embedding API|当前没有自动重试|
|整个 /add 或 /search 请求|服务端不进行无界整请求重放；失败可能仍向调用者返回 502 或其他错误|

故障注入验证：Qwen 首次 502、第二次成功，实际调用 2 次；分类器持续 502，实际调用恰好 3 次后抛出失败。测试未改变模型提示词或重试策略。

全量测试中的 3 次 Add 502 是接口错误，不能单凭状态码断定为百炼故障；分类器也可能因模型输出验证失败返回 502。之前全量脚本的外层重试属于测试客户端，不是部署服务的内置自动恢复。

调用者应对临时网络错误、429/502/503/504 做有限退避重试，例如最多 3 次；Add 必须沿用相同 user_id、request_id、session_id 和原始消息，不能每次换 ID。收到 401、409、422 应检查凭据、幂等冲突或请求，不应盲目重试。若上游持续不可用，重试仍可能耗尽；当前策略不保证完全消除 502。

## 后续更换服务器千问 Key

编辑 `/GeeAI/AIAgent/CSIG/.env`：

```dotenv
RAG_EMBEDDING_API_KEY=新的百炼Key
RAG_RERANK_API_KEY=新的百炼Key
```

若只更换重排服务的 Key，只改第二项。当前重排 Key 使用服务器已有 embedding 凭据初始化；这两个字段是独立的，修改 embedding 字段不会自动同步另一项。若地域或工作空间变化，还需要匹配修改各自 API URL。不要修改 AML_API_KEY，除非要同步更换赛事调用凭据。

完成后运行 `systemctl --user restart csig-aml-v1.service`，并再次检查 health 与实际 Add/Search。只有 root `.env` 生效，不读取系统环境变量。临时验证实例已停止，生产库及回滚快照保留。
