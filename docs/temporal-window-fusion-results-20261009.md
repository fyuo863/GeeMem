# 时间窗口融合真实测试

本次实现基于提交 `1605c6b` 的绝对时间查询方案，并在 `0ba8f9d` 的窗口候选基础上增加：

- 时间窗口候选与全局候选共用固定 400 条重排预算；
- 重排后加入有限时间语义分数，默认权重 0.10；
- 同会话相邻消息只获得 0.3 倍弱时间分数；
- TopK 默认最多保留 50% 的高置信度窗口证据，其余位置由统一排序补齐；
- 没有参考时间或时间无法解析时，回退普通全局检索；
- 不增加 LLM 调用，不重新生成历史向量。

## 测试协议

使用 20 道 LongMemEval `temporal-reasoning` 和 40 道控制题，共 60 题；完整历史 39,974 个块、107 条金标消息。通过本地 FastAPI `/search` 测试，使用 `text-embedding-v4`、英文 MiniLM reranker、400 条重排候选和 Top10。多跳、分区路由和新时间 LLM 标注均关闭。两组都使用相同的 `question_date` 作为参考时间；基线是方案 B 的绝对时间查询。

## 结果

| 范围与指标 | 方案 B | B + 窗口融合 | 变化 |
|---|---:|---:|---:|
| 时间题 Hit@5 | 95.00% | 100.00% | +5.00 pp |
| 时间题 Recall@5 | 78.67% | 87.00% | +8.33 pp |
| 时间题 Micro Recall@5 | 67.44% | 74.42% | +6.98 pp |
| 时间题全证据命中@5 | 70.00% | 80.00% | +10.00 pp |
| 时间题 Hit@10 | 95.00% | 100.00% | +5.00 pp |
| 时间题 Recall@10 | 84.83% | 93.17% | +8.33 pp |
| 时间题 Micro Recall@10 | 79.07% | 86.05% | +6.98 pp |
| 时间题全证据命中@10 | 75.00% | 85.00% | +10.00 pp |
| 全部60题 Hit@5 | 91.67% | 93.33% | +1.67 pp |
| 全部60题 Recall@5 | 81.50% | 84.28% | +2.78 pp |
| 全部60题 Hit@10 | 96.67% | 98.33% | +1.67 pp |
| 全部60题 Recall@10 | 88.11% | 90.89% | +2.78 pp |

40 道非时间对照题的 Hit、Recall、Micro Recall 和全证据命中指标均未变化。4 道已解析时间题的排名发生变化，其中旅行排序题由 Recall@10 仅命中 1/3 条变为 3/3 条，比赛购物题从未命中变为命中。

平均检索耗时为基线 655.3 ms、窗口融合 661.3 ms，增加约 6.0 ms（约 0.9%）。查询 embedding 预热，耗时不含远端 embedding API；因此这是本地检索与重排部分的配对测量，不是完整端到端延迟。

## 结论与边界

本次提升来自窗口证据在重排后仍保留有限配额，并将时间匹配作为弱信号参与融合。此前窗口候选本身没有增加覆盖，因为正确证据已经进入 400 条候选；真正改善的是它们不再被重排完全压到 TopK 之外。

该方案仍依赖可靠的事件时间标注和调用方提供的参考时间。日期被提及不代表整条消息的事实都发生在该日期，因此保留了全局通道和 50% 的软配额。严格时间过滤尚未启用。
