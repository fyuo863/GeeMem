# 多跳来源绑定与证据需求修复测试（2026-10-03）

## 结论

实现提交 `6b24b8b`，修复前检查点 `17bc348`，分支 `codex/llm-multihop`。来源绑定和依赖检查已实现，真实调用能完成逐步发现实体的三段链，但没有证明公共题集总体召回提升。组合方案 Recall@10 与原多跳均为 80.11%，平均 Search 耗时从 9.99 秒增加到 14.24 秒（约 +42.6%）。两个增强开关保持默认关闭，不替换生产方案。

## 实现与边界

- `RAG_MULTIHOP_BINDINGS=on`：模型选择来源、原文片段、实体锚点与查询模板；程序校验唯一精确匹配，分配真实来源 ID、字符位置和绑定 ID，并插入实体。问题中的 Q0 不作为证据。限制每次 Search 最多一次结构化纠错，纳入 LLM 总预算。
- `RAG_MULTIHOP_NEEDS=on`：规划最小证据需求和前置依赖，逐项记录 supported/missing/conflict/time_unknown；只有需求齐全、引用有效且依赖闭合才能宣布充分。模型省略需求不能直接停止。
- 下一轮只接收以前有效的引用，不接收旧的缺失结论，避免复制过期判断。增加无进展停止和统一调用预算。
- `/search` 仍返回原文，不生成最终答案；`/add` 不调用规划器。绑定与需求状态仅存在于请求 trace。
- 精确引用校验只证明文字来自指定来源，不证明实体角色、关系方向、需求规划或语义蕴含正确。

实现细节与复现参数见 [设计文档](multihop-evidence-repair.md)。根目录 `.env`、默认线上配置和服务器部署均未修改。

## 测试协议

自动化测试：`python -m pytest -q -p no:cacheprovider`，146 passed（6.93 秒）。覆盖来源错误、歧义引用、依赖遗漏、冲突、时间不明、预算、回退、用户隔离和 Add/Search 原文契约。

真实模型：gpt-4o-mini；embedding：text-embedding-v4（1024 维）；reranker：MiniLM CUDA。配置只读取项目 `.env`。manifest 中保留的本地 BGE 路径为备用设置，本次实际使用 v4 API。

公共测试使用与此前相同的 30 道题，六类各五题，排除先前 pilot8；完整写入所选题目的历史，共 1437 个 session、14913 条消息、47 条标注证据。每题五种方案共 150 次 Search，轮换执行次序；仅复用文档向量与数据库副本，不缓存查询向量。测试为进程内真实 Add/Search，非公网负载测试。不向检索或 LLM 提供标准答案。这里衡量消息级证据召回，不是回答准确率或官方榜单成绩。

另设六个受控功能场景，top_k=3、每子查询候选数=1，检验实体尚未知时能否真正发起后续查询，共 30 次 Search。

最终数据目录：

- `data/multihop/repairs-ablation30-20261003`
- `data/multihop/repairs-chain6-final-20261003`

早期网络阻塞的 `repairs-chain6-20261003` 和用于定位过期判断的 `repairs-chain6-live-20261003` 不纳入最终指标，不拼接各次最好结果。源文件哈希记录在 manifest，汇总快照随本报告提交。

Hit@k：至少命中一条标注证据的题目比例；Recall@k：逐题证据召回率的宏平均；Micro Recall@k：全体命中证据数 / 全体标注证据数；全证据命中@k：所有标注证据均进入前 k 的题目比例。

## 真实链路案例

成功：Nadia → 配偶 Elias → 公司 SolsticeAnalytics → CEO RuthChen。组合方案两轮、三次 LLM 调用取回 3/3 证据；原多跳仅 2/3。

成功：Iris → 导师 Dario → 任职 AuroraSystems → 总部 Oslo。组合方案三轮、四次 LLM 调用取回 3/3；原多跳仅 1/3。这证明能根据前轮新实体执行后续检索。

失败：问题是“Veda 的兄弟的老师教什么乐器？”正确链为 Veda 的兄弟 Niko → 老师 Selene → 教单簧管。组合方案却规划了“兄弟演奏什么乐器”，把 Niko 喜欢听大提琴当成支持，又用 Veda 跟 Pascal 上课及 Pascal 教小提琴的原文替代 Niko 的老师关系。最终仅 1/3 标注证据，却宣布 sufficient。出处真实不等于归属和语义正确，需求列表自身也可能偏离原问题。

Leona 场景组合方案虽返回完整证据，但发生路由 ConnectError 后走基线回退，不能算作成功的模型多跳。

## 公共题中的剩余问题

`6a1eabeb` 问个人慈善 5K 最好成绩。组合方案找到 27:12，却额外要求“确定用户身份”，并将其列为未满足需求。当前请求已按用户隔离，这种额外条件不是回答原问题所必需，导致过度规划。

`gpt4_7f6b06db` 问过去三个月三次旅行的先后顺序。原多跳前十有 1/3 证据，仅绑定版前十变成 0/3。两版均无网络回退，因此是实际回归。绑定版生成了 Golden Week 的活动、健身课程改善、集邮主题等偏离原问的查询；各轮有效支持 ID 均为空。新增噪声候选经过原有融合排序挤掉证据，不能归因于支持证据强制置顶。

仅绑定版另在 `gpt4_f2262a51` 多找回 1/5 证据，但不足以抵消旅行题丢失 1/3 对宏平均的影响。来源可追踪并不自动保证查询相关性。

## 后续优先级

先约束需求计划忠实保留原问题的关系和最终目标，禁止无必要的身份前置条件；再校验实体角色和关系是否一致，最后在合并候选前拦截偏离原问题的查询。当前版本适合作为可审计实验基础，不应以“出处校验通过”替代语义正确性验证。本轮不再追加调参，以保留最终对比的可解释性。
