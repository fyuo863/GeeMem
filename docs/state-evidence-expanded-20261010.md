# 状态证据选择器扩大测试（2026-10-10）

本轮冻结 `codex/state-evidence-pilot` 现有提示词和排序逻辑，只增加评测脚本，不用失败题继续修改实现。配置来自根 `.env`，选择模型为 gpt-4o-mini；不变更线上服务与默认开关。

## 三层评测与可比边界

1. **公开集候选重放**：读取上次完整测试的 861 道 LoCoMo-Refined 文本题，859 道有金标。保留既有完整流程 Top100 候选，调用真实选择模型后比较排序。原文按保存 ID 从对应隔离 SQLite 库只读获取，未重跑写入、embedding、reranker 和规划器；原 score 未保存，用单调递减占位分数保持原顺序。它是选择阶段的配对消融，不是新一轮端到端全量测试。
2. **合成候选压力测试**：20 个中英场景，每题 16 条候选，分别将金标放在前、后和固定随机位置，共 60 次真实选择调用。包含上次 8 个案例和新增 12 个场景；不是 60 道独立题，也不是未见公开测试集。干扰项含明显无关公告，增益不能解释为生产排序提升。
3. **共享库真实接口测试**：20 个场景的原文进入同一隔离用户，增加跨人物、跨话题竞争；调用本机 FastAPI `/add`、`/search`，开启/关闭状态选择器做配对测试，保留现有规划、分区、embedding 和 reranker。独立运行可能受上游 LLM 随机性影响；关闭请求 top_k=10，开启内部至少取 16，因而不是纯选择器消融。与候选压力测试短暂并发，耗时包含供应商波动。

指标：宏平均 Recall@5/10、Hit@5/10、Micro Recall@5/10、全证据命中@5/10、MRR、首条金标命中、逐题提升/退化、直接依据选择 Precision/Recall/Exact Match、调用次数、失败回退和耗时。均为证据指标，没有引入答案生成评分器或宣称官方维度分数。

## 候选压力测试：找相关证据有效，状态裁决仍不稳定

|---|---:|---:|
| Recall@5 | 41.39% | 98.89% |
| Recall@10 | 53.61% | 98.89% |
| Hit@5 | 43.33% | 100% |
| Hit@10 | 56.67% | 100% |
| Micro Recall@5 | 42.31% | 97.44% |
| Micro Recall@10 | 53.85% | 97.44% |
| 全证据命中@5 | 40.00% | 96.67% |
| 全证据命中@10 | 50.00% | 96.67% |
| MRR | 0.4185 | 0.8833 |
| 首条金标命中 | 35.00% | 76.67% |

60 次中 Recall@10 改善 29、退化 0；首条改善 25、退化 0。选择器平均调用 1.39 秒，失败回退 0。

模型标记为 primary 的集合与人工金标相比：宏平均 Precision 74.72%、Recall 97.50%、完全一致率 43.33%。这是更严格的状态证据选择指标，**不是最终 Top10 的召回率**。说明模型倾向多选，能够纳入正确内容，但常把不应作为当前事实的内容也一起提升。

同样的场景仅改变候选顺序，增强后的首条正确率：金标靠前 100%、金标靠后 60%、随机顺序 70%。该差异同时包含模型选择的顺序敏感性和程序“同 primary 级别保留原顺序”的作用，不能全部归因于模型。

### 典型错误

- **明确替代仍当冲突**：小林已离开甲公司、现在在乙公司，模型把旧、新两条都标为 primary，旧条靠前时不能纠正首位。
- **对象归属混淆**：问 Ken 当前电话，`Ken: My number is 555-1100.` 和 `Ken: My colleague Kai just changed his number to 555-2200.` 同时被标为 primary。
- **例外条件不匹配**：问普通办公室出租车审批，模型仍提升“急诊医院无需审批”的例外。真实引文并不等于适用证据。
- **将来生效与当前生效**：给定 2025-02-01 问当前会费，3 月才涨价的通知仍可能与当前费用同级。

### 人工金标的敏感性

`cancelled_change`（取消跳槽、仍在原公司）和 `temporary_location`（短期旅行、住址不变）的早期来源也可能支持同一答案，但初始严格金标只收录最终确认消息，因此 Top1/primary 判断可能过严。完整结果保留原金标，不事后覆盖；另排除这 2 个场景做敏感性分析：18 场景 ×3 顺序，增强首条命中 79.63%、primary 完全一致 48.15%，仍不能支持“已准确处理当前状态”的结论。规则案例的全依据金标也更偏向完整列出条件，不等同于最小充分答案证据。

## 最终结论

**尚未证明当前值、规则适用性等缺失能力在真实检索中得到提升。** 公开候选重放与共享库接口测试的指标均未提升，接口平均耗时增加约 20%。人为乱序测试证明本模块能找回相关证据，但高 Recall 隐藏了“错误内容也被标记为直接依据”的问题。

建议维持默认关闭。下一步应把当前值更正、适用例外、未来生效等判断从一般相关性选择中分离，在每次只给少量同主体候选的条件下测试可验证的成对关系，并保留不确定状态；不能仅放宽触发词或提高整体加权就宣称修复。

本轮没有重新调用官方 Smoke，不能给出 D1/D2/G2 或其他官方子维度的新分数；没有完成删除/遗忘、摘要、隐私和迁移能力的评测。时间与多跳问题也未因本模块而获得覆盖，仍需各自专项测试。
