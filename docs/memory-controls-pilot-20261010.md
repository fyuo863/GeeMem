# 跨阶段、规则、版本与披露控制首版

本机实现，不变更远端。保持统一底层检索及原文证据包，不引入第二套向量库或生成事实库。

## 已实现

### 发布版本与固定读取

`rag_publications` 记录成功完成原文写入、时间索引和类型索引的请求。只有完整完成 `/add` 后才发布，失败请求可沿用相同 request_id 恢复；重试不产生第二条发布记录。原文仍追加保存，没有覆盖旧事实。

`RAG_VERSION_MODE=on` 时，Search 开始取得当前用户已发布的最高版本，多跳原查询、并行子查询、恢复查询和补查通过 ContextVar 固定读取这一版本。检索前过滤未发布/较晚发布的请求，再进行排序及邻近上下文构造。外部请求不能指定未来版本。独立 AtomicRetriever 调用读取当时最新已发布版本；需要跨调用一致时必须经 SearchService 编排。

首次迁移将既有 `rag_requests` 中没有未完成队列的记录作为历史已发布数据；无法追溯证明旧版每条时间索引是否完成，因此该历史迁移不是重新校验。以后完整写入持续登记发布，即使读取版本开关关闭也不会漏登记。程序使用发布先后，不把消息时间当事实生效时间。版本号只保证递增，不保证连续。

这不是完整事实版本系统：没有自动 supersedes、有效期推断、撤销/删除接口，也没有“当前事实表”。当前底层是追加写入，快照保证可见源集合一致；未来若允许修改已有索引或政策，需要另外对这些派生状态做版本化。

### 基础披露策略

`RAG_DISCLOSURE_MODE=mask` 由服务器配置控制，问题文本不能解除它。程序检测邮箱、中国大陆手机号、常见北美号码、18位证件号格式及 `password=...`、`api_key:...` 等显式凭据，使用 `[REDACTED:类型]` 替换。

来源文本在检索侧重排之前遮蔽；返回给规划/审核的候选与私有相邻上下文也遮蔽，返回前再次检查。可选结构化 context 暂时清空，避免从旁路返回未检查的原文。敏感原文仍在存储层，不改写源记录。遮蔽后的来源使用稳定 `view_...` 标识，`rag_disclosure_views` 保存同用户视图到原始记忆 ID 的映射。证据包可能引用 view ID，追溯时先查视图表，再查源表。

限制：不是通用敏感信息识别器或字段级身份授权引擎，不覆盖所有语言、地址、银行卡、健康/家庭等语义隐私。规则也可能误判或漏判。**不遮蔽 `/add` 在 embedding/分类供应商侧的输入，也不保证用户问题本身不含敏感字段**；当前保护范围是检索来源内容的后续披露。外部模型供应商是否可处理原始写入数据属于独立配置和授权边界。

### 跨阶段与规则补查

`RAG_SUPPLEMENTAL_MODE=on`，在已有 long/short 多跳流程的初始召回后，对明确的规则/例外/审批/退款类词或计划/变化/取消/结果类词触发一次补查。原问题原样保留，附加对应的中英文阶段或条件检索提示。补查仍调用同一检索与分区流程，候选最多 12 条。

补查计入 `RAG_MULTIHOP_QUERIES` 的现有总预算；没有剩余查询预算或时间时跳过。一次 Search 最多一次，不在每个子查询重复扩展。现有分区判断仍可能增加调用；补查本身没有增加另一个选择模型。原有审核提示补充适用条件、同一事项、计划与完成的区别；模型仍只输出证据引用及有限查询。最后由既有证据包拼接审核选中的原文。

这是一版有界候选扩展，不是持久化阶段图、规则执行引擎或高准确率规则裁决。附加宽泛词可能引入噪声，审核可能误选；unknown 保留在原审核不足状态，不强行生成事实关系。focused 实验路径尚未接入补查。

## 运行与验证

配置来自根 `.env`，所有新增模式在 `.env.example` 默认 off。本机真实测试用独立 SQLite 库，脚本 `scripts/test_memory_controls_real.py`；不使用生产记忆。

专项测试涵盖失败索引不可见、重试发布幂等、后续增量写入不会污染已固定读取版本、并行线程继承快照、重启和开关切换、遮蔽后仍可追溯原文、跨用户隔离、普通问题不触发补查及共享预算上限。

真实场景采用 3 个增量会话、7 条人工原文；5 道问题分别测试行程变化、急诊规则、普通通勤规则、就职信息中的敏感字段、其他人物信息。10 次 Search 比较补查 off/on；两组均开启版本与披露控制以及证据包，因此该对照只衡量补查，不是全部新增功能的准确率对照。指标为返回内容中完整金标来源覆盖，隐私题只校验必要的非敏感事实片段。

正式评测部署前，还需更大样本验证误屏蔽率、敏感漏出率、条件不适用例外混入率，以及跨阶段错误关联。单次小测不能证明官方 D/G/H/I 等维度提高。

## 本次真实调用结果

最终全套自动化回归：354 项通过（包含本轮 9 项控制专项测试），耗时 11.13 秒。

记录：`data/memory-controls/20261010T055651Z/report.json`。3 次新增 Add 和 3 次相同请求重试成功，发布版本保持幂等；10 次 Search 成功且读取版本保持不变，跨用户空结果检查通过。所有返回均未出现测试邮箱和手机号原值。

| 另一人物的旅行事实 | 1/1 | 1/1 | 6.41 / 5.62 秒 |

**发现的未解决问题**：普通办公室出租车题，尽管正确规则被召回，开启补查后的模型审核仍将不适用的急诊例外纳入同一证据包。来源覆盖 100% 没有反映这一错误。首版只完成规则候选补全与审核提示，没有验证可靠的适用性裁决。因此补查开关暂不写入本机默认配置，仍默认 off；版本读取与基础遮蔽也仅在隔离测试配置中启用，待用户确定策略后用于实际记忆库。

遮蔽模式会对本人手机号请求同样遮蔽，没有细分“经授权可披露”身份；不能把此结果宣称为完整 H 隐私能力。旧有事实替代和语义隐私仍保持未实现状态。
